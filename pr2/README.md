### 1. Напишіть програму для визначення моменту, коли time_t закінчиться. Дослідіть, які зміни відбуваються в залежності від 32- та 64-бітної архітектури. Дослідіть сегменти виконуваного файлу.

Для виконання завдання була реалізована програма. Оскільки мій пристрій має 64-бітову архітектуру, на ньому. Для тестування 32-бітової архітектури було необхідно встановити необхідний пакет за допомогою команди 
```
sudo apt install gcc-multilib
```
Також був використаний відповідний прапорець 
```
-m32
```
#### Код програми
```c
#include <stdio.h>
#include <time.h>
#include <stdint.h>

int main() {
    time_t t;
    int bits = sizeof(t) * 8;
    
    printf("Architecture: %d-bit\n", bits);

    long long max_seconds = (1LL << (bits - 1)) - 1;
    printf("Mathematical max seconds: %lld\n", max_seconds);

    time_t test_time = (time_t)max_seconds;
    struct tm *time_info = gmtime(&test_time);

    while (time_info == NULL && test_time > 0) {
        test_time >>= 1; 
        time_info = gmtime(&test_time);
    }

    if (time_info != NULL) {
        printf("Last processable date by your system (UTC): %s", asctime(time_info));
        printf("Corresponding seconds: %lld\n", (long long)test_time);
    } else {
        printf("Error: Could not convert any positive time value.\n");
    }

    return 0;
}
```

#### Висновок
Були досліджені відмінності поведінки типу даних time_t в залежності від архітектури:
- 32-бітна архітектура - оскільки time_t має розмір 4 байти, він переповнюється 19 січня 2038 року, після чого час "відкочується" у 1901 рік;
- 64-бітна архітектура - розмір time_t становить 8 байт. Теоретично це розширює межу часу роботи архітектури на сотні мільярдів років, і хоча є бібліотеки по типу GMP де можна працювати з числами будь-якої довжини, але стандартна бібліотека glibc, яка оперує датами, має логічне обмеження у 1.1 мільярдів років для запобігання помилкам в алгоритмах календарних розрахунків.
