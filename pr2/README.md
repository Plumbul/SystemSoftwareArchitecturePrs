#### Код програми
```c
#include <stdio.h>
#include <time.h>
#include <stdint.h>

int main() {
    time_t t;
    int bits = sizeof(t) * 8;
    
    printf("Architecture: %d-bit\n", bits);

    long long max_seconds = (1LL << (bits - 1)) - 1;
    printf("Mathematical max seconds: %lld\n", max_seconds);

    time_t test_time = (time_t)max_seconds;
    struct tm *time_info = gmtime(&test_time);

    while (time_info == NULL && test_time > 0) {
        test_time >>= 1; 
        time_info = gmtime(&test_time);
    }

    if (time_info != NULL) {
        printf("Last processable date by your system (UTC): %s", asctime(time_info));
        printf("Corresponding seconds: %lld\n", (long long)test_time);
    } else {
        printf("Error: Could not convert any positive time value.\n");
    }

    return 0;
}
```

#### Висновок
Були досліджені відмінності поведінки типу даних time_t в залежності від архітектури:
- 32-бітна архітектура - оскільки time_t має розмір 4 байти, він переповнюється 19 січня 2038 року, після чого час "відкочується" у 1901 рік;

Висновок
Локальна змінна i розташована у сегменті стек. У 64-бітних системах Linux стек зазвичай розміщується у верхній частині віртуального адресного простору, тому ми бачимо такі високі значення адрес. При повторному запуску програми адреса щоразу трохи змінюється. Це є результатом роботи механізму ASLR (Address Space Layout Randomization) - системи безпеки, яка щоразу випадковим чином зміщує розташування сегментів у пам'яті, щоб ускладнити проведення хакерських атак.

Висновок
Дослідження показало, що статичні сегменти займають нижні адреси адресного простору, причому Data та BSS ростуть у процесі виконання лише за наявності глобальних або статичних змінних. Купа розміщується вище цих сегментів і розширюється в бік збільшення адрес. Стек навпаки, розташовується у верхній частині пам'яті та росте вниз: при кожному виклику функції та оголошенні великих локальних масивів адреса вершини стека зменшується. Локальні масиви не відображаються у звіті утиліти size як частини сегментів Data чи BSS, оскільки вони існують лише динамічно під час роботи програми; при цьому ініціалізовані локальні дані збільшують розмір сегмента Text, де зберігаються початкові значення для їх копіювання в стек.
